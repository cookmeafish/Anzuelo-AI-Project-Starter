# Engine v2: one reminder at the start, one real check at the end

status: in progress

The user's model: a hook at the start reminds the agent what the request requires, and a hook at the end checks that it
really happened. v1 grew to about 9,600 lines of hooks, 8,800 lines of self-tests and about 40 lines of hints per
prompt. Most of its later fixes were for friction the engine made itself. Stage 1 ([[2026-11-05-quiet-engine]]) makes
v1 quiet during work. v2 replaces it. Linked: [[2026-11-05-v30-findings]].

## Design
- **Start (prompt hook), at most about 10 plain lines:** the runbook that fits, its "Done when" list as the
  requirements, and the user's standing rules that touch this request. No REQ tags, no check names, and no notes
  about the engine itself.
- **During work:** silent. A small safety guard refuses only what can't be undone, what leaks, or what breaks a
  protection the user set. That covers secrets, AI attribution, protected and versioned files, outward actions,
  risky git, mixing people's data, and password prompts.
- **End (Stop), checked for real:** each requirement from the start is checked against this session's own
  transcript:
  - the files the answer says changed exist and did change;
  - the tests it says passed ran and passed (from the tool results);
  - the answer claims nothing that didn't happen.
  Only this session's own edits count, never the git status of the shared tree. It reads the user's request before it
  calls an action a mistake. At most one block, with a short plain list. No ledger lines, waivers, or carryover
  between turns. Items no script can check are dropped or judged by a model hook where the host has one, with a plain
  fallback for other agents.
- **Helpers and text-only answers:** no checklist and no gate.
- **Size budget, enforced by a self-test:**
  - the engine (all hooks) stays under about 1,500 lines;
  - at most about 15 end checks;
  - each check names a real miss it caught in two unrelated kinds of project. A check that fits one domain goes in
    that project's own runbook.

## Tasks
### Task 1: measure v1 on real data (baseline)
- [ ] `tools/starter/interrupts.mjs` counts the interruptions during work, the blocks per turn, and the bookkeeping
  lines demanded, from real transcripts.
- [ ] Baseline for both watched projects and the trial projects, with no-engine trial rounds as the floor.
- [ ] Collect a set of real misses that v1 caught at the end (claims with no evidence, tests reported as passed
  that failed, a runbook's key step skipped), from several kinds of project.
- [x] Baseline since 2026-10-25, per user turn (`interrupts.mjs`):
  - Larger project, main session: the prompt hook adds 11.9 lines and 2,607 characters per turn. During the work there are 1.57 notices and 0.34 refusals that are not for safety. Stop blocks 0.68 times per turn.
  - Larger project, helpers: 0.22 notices and 0.10 refusals that are not for safety, per turn.
  - Smaller project, main session: the prompt hook adds 32.9 lines and 7,910 characters per turn. There are 4.68 notices during the work, and Stop blocks 1.41 times per turn. Replay this one first: it is the worst case.
- [x] Value side (`stop-value.mjs`): after a Stop block the agent did real work (an edit outside the notes, or a test, build or check run) after 93 of 119 blocks in the larger project and 26 of 31 in the smaller one.
  - **The kinds that most often led to real work:** a claim with no evidence, tests or build not run, the health check, the security review, the screenshot review, where new knowledge facts came from, a complaint's lesson, and an open plan.
  - **Bookkeeping kinds:** "Record N of the checklist", "Name the runbook", "End with the whole answer". v2's end check is built around the first list.
- [ ] Rewrite each runbook's "Done when" as outcomes a script can check: a file exists or changed, a command ran and passed, the answer names something. The start hook shows the list, and the end hook checks the same list. The rest go to a model judge or are dropped.
- [ ] Size-budget the rules too. What the start hook injects plus the rules that are always loaded should fit on one short page. Each rule points at the end check that enforces it, or at nothing if it is guidance.
