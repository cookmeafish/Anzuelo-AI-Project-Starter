# Plan: the engine and every project using it leave nothing that slows the computer

**Goal:** no run of the engine, its tests or a project's tests leaves files, folders, processes or kernel memory that
pile up. Proven by a soak, not by one run.

**Spec (user, 2026-11-12):**
1. The engine and every project using it must have no leaks that slow the computer.
2. Every place the engine or its tests write or start things is known: what writes it, whether it is cleaned, its size,
   its growth per chain.
3. Each leak is fixed at the source: create less, and clean up what is created.
4. Every chain fails when anything grows past a small budget (the leak check).
5. Nobody says "fixed" before a soak of 4 chains back to back on a freshly restarted machine, the pool and every
   location logged every 5 minutes, ends with nothing past its budget and the pool within 300 MB of the start.

**Approach:** measure every location (the sweep below), fix each at its source with a test, keep the leak check in
every chain, then the soak.

**Confidence:** 6/10. Main risk: the kernel pool also grows from Defender's and the file system's per-file tracking
(tags FMfn, Ntff, FMsc, MPsc), which only fewer file creations can lower; the soak shows whether that is enough.

**How to resume:** run `node skills/plan/scripts/plan-tasks.mjs next docs/plans/2026-11-12-no-leaks.md`, or find the
first unticked box. Ticked boxes are done; never redo them.

## Constraints for every task
- Each fix has a test that fails without it.
- Never delete what already exists (old caches, transcript folders, temp files): list it for the user, who decides.
- Light runs only; every run counts toward the pool.

## Watch for
- A project's own scripts writing to its `.cache/`: reported to that project, not changed from here.
- Antivirus scanning adds pool per new file: fewer files created is the only lever the engine has.
