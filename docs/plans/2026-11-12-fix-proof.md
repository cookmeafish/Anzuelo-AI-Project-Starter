# Plan: a fix is proven on the failure it fixes, not patched over

**Goal:** a turn that fixes a problem shows the original failure failing before and passing after, from its own tool
calls; a patch that only hides one case is caught; a problem back within 14 days gets a plan and a sweep, not another
patch. Queue item 2b (tools/starter/STATUS.md), before the fourth project comes in.

**Spec (oversight, 2026-11-12):**
1. Every fix turn goes through the debug skill.
2. Before/after proof on the original failure, from the turn's own calls.
3. Patch detection: a special case keyed on the report's example, or a bare guard or retry.
4. A repeat within 14 days needs a plan plus a sweep.
5. A replay of real fix turns proves the checks hold and stay quiet where they should.
Also: the health check's unproven "fails after this change" line (done below, Task 0).

**Constraints:**
- A fix turn is judged by the agent's own record, never the user's words (no check starts from the prompt, retired
  2026-11-07): an Issue line, the debug skill opened, or a test the turn wrote that failed and then passed.
- Only proven items reach the user; a check that cannot tell says nothing. No new interruption during work (rule 18):
  everything here is in the end check.
- The end budget is full (3200/3200): each new line replaces one, or the budget rises only with a reason oversight
  accepts.

**How to resume:** `node skills/plan/scripts/plan-tasks.mjs next docs/plans/2026-11-12-fix-proof.md`.

## Task 0: the health line says only what is proven
**Files:** tools/hooks/v2/lib.mjs (healthGaps), tools/hooks/v2/selftest.mjs, tools/hooks/selfcheck.mjs (patterns).
- [x] Each audit run the end check makes is recorded (tools/hooks/state/audit-fails.json); a failure the last run before
      the turn listed is already there and not held; "after this change" only when a run before the turn lacked it.
- [ ] Run `node tools/hooks/v2/selftest.mjs` and `node tools/hooks/selfcheck.mjs --tags audit-run,twin-sync,skill-valid`
      after the release chain. Expected: ALL PASS.

## Task 1: a fix turn is known, and routes through debug
**Files:** tools/hooks/v2/end.mjs (fixTurn), skills/debug/SKILL.md, tools/hooks/v2/selftest.mjs.
- [ ] `fixTurn(acts)`: a complaint turn (complaintTurn) that changed code, or a turn that opened skills/debug/SKILL.md.
- [ ] In a fix turn that never opened the debug skill, the end check names it once ("open skills/debug/SKILL.md and
      follow its phases"); a turn with no code change is never asked.
- [ ] Tests: a complaint turn with a code edit and no debug read is asked; with the read, or with no code change, not.

## Task 2: before and after, from the turn's own calls
**Files:** tools/hooks/v2/end.mjs, tools/hooks/v2/lib.mjs (proofTurn's runs), tools/hooks/v2/selftest.mjs.
- [ ] In a fix turn, a run of the same command (a test, a script, the reproduction) failed before the first code edit
      and passed after the last one. The runs come from proofTurn (each run has editedBefore).
- [ ] Missing: one line naming what is missing (no failing run before, or no passing run after), with the hint to run
      the reproduction on the old code (`git stash` or `git show HEAD:<file>`). A turn whose answer says plainly why it
      cannot be reproduced ("NOT VERIFIED: ...") is not held.
- [ ] Tests: fail-before/pass-after passes; pass-only, fail-only and different commands are held; NOT VERIFIED is not.

## Task 3: a patch that hides one case
**Files:** tools/hooks/v2/lib.mjs (patchGaps), tools/hooks/v2/selftest.mjs.
- [ ] Added code (the turn's Edit new_string minus old_string) with a literal from the complaint's own example (a
      quoted string or number from the Issue line, at least 6 characters) inside a condition (`if`, `===`, `includes`,
      a regex) is named: "this fix keys on the example; fix the cause".
- [ ] Added code that only wraps the failing call in a bare `try { } catch { }`, a retry loop, or a raised timeout,
      with no other change, is named the same way, unless the answer says why it is the cause.
- [ ] Tests: each pattern held; a general fix that mentions the example only in a test file or comment is not.

## Task 4: a repeat within 14 days
**Files:** tools/hooks/v2/end.mjs, tools/hooks/v2/selftest.mjs.
- [ ] An Issue line whose problem shares most key words (late.mjs keys) with one in the project's records of the last
      14 days (the dated turn-notes archive, docs/CHANGELOG.md lessons) is a repeat.
- [ ] A repeat turn ends only with a plan in docs/plans/ written or updated this turn and a sweep run over real data
      (a run whose output covers more than the one case), or a plain reason in the answer.
- [ ] Tests: a repeat without a plan is held; with plan and sweep, not; an unrelated Issue, not.

## Task 5: replay real fix turns
**Files:** tools/starter/replay-fixes.mjs (new), tools/starter/reviews/.
- [ ] Pick 20 real fix turns from the projects' transcripts (Issue lines, debug reads), run Tasks 1-4 on each, and
      judge each result by hand: right hold, false hold, missed. Report in tools/starter/reviews/.
- [ ] Expected: no false hold on a turn that really proved its fix; each false hold fixed at its source before release.

## Task 6: run and release
- [ ] `node tools/hooks/v2/selftest.mjs` (ALL PASS, sizes within budget), `node tools/audit.mjs` (PASS), then the
      release chain.
